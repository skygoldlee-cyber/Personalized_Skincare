## 1. 핵심 전략: Pass Loop → Practice Loop

### 1.1 문제 인식

일반 자격증 플랫폼은 합격하면 구독자가 이탈합니다:

```
교재 → 학습 → 문제 → 오답 → 합격 → ❌ 이탈
```

그러나 **맞춤형화장품조제관리사는 자격 취득 후에도 지식이 계속 필요한 분야**입니다. 처방전 작성, 원료 검색, 배합 계산, 법령 준수 등 실무에서 시험 지식이 그대로 활용됩니다.

### 1.2 전략 방향

```
              ┌───────────────┐
              ↓               │
교재 → 학습 → 문제 → 오답 → 합격
                              │
                              ↓
                       🧴 실무 모드
                              │
                 ┌────────────┼────────────┐
                 ↓            ↓            ↓
              처방 참고     원료 검색     배합 계산
                 ↓            ↓            ↓
              제품 기록     고객 관리     성분 검토
                 └────────────┼────────────┘
                              ↓
                         새로운 처방 경험
                              │
                              └────→ 학습/지식 축적
```

### 1.3 제품 정의 확장

| 기존 정의 | 확장 정의 |
|----------|----------|
| "사용자를 합격 상태까지 자동으로 끌어가는 플랫폼" | **"합격시키고, 합격 후에도 계속 쓰게 만드는 플랫폼"** |

### 1.4 핵심 원칙

> **합격은 이탈 이벤트가 아니라 플랫폼의 다음 단계로 진입하는 이벤트다.**

## 2. 조제관리사 실무 DB

### 2.1 개요

시험이 끝난 뒤 사용자가 가장 자주 찾는 것은 "이 원료를 어떻게 활용하지?"입니다. 시험 공부에 사용했던 지식 DB를 그대로 실무 DB로 전환합니다.

### 2.2 원료 상세 페이지 구성

원료 하나를 검색하면 다음 정보를 통합 제공합니다:

```
히알루론산

[기본 정보]
INCI Name: Sodium Hyaluronate
원료 유형: 보습제
기능: 수분 보유, 피부 장벽 강화

[제형별 적합도]
토너      ★★★★★
세럼      ★★★★★
크림      ★★★★☆

[배합 참고]
권장 범위: 0.1% ~ 2.0%
제형별 사용량:
  - 토너: 0.1% ~ 0.5%
  - 세럼: 0.5% ~ 2.0%
  - 크림: 0.1% ~ 1.0%
주의사항: 고농도 시 점도 급증

[궁합]
◎ 잘 맞는 성분: 글리세린, 나아신아마이드, 판테놀
△ 주의 성분: 고농도 비타민 C (pH 충돌)

[처방 활용]
보습 처방: 히알루론산 + 글리세린 + 세라마이드
장벽 처방: 히알루론산 + 세라마이드 + 판테놀
민감성 처방: 저농도 히알루론산 + 알란토인

[관련 규정]
별표 2 사용 제한 원료: 해당 없음
별표 4 표시 기준: 해당 없음
식약처 고시: 화장품 원료 등 고시 (제2024-xx호)
```

### 2.3 데이터 소스 매핑

| 실무 DB 섹션 | 기존 시험 데이터 소스 | 추가 필요 데이터 |
|-------------|---------------------|-----------------|
| 기본 정보 | `content/참조자료/원료/*.md` | INCI Name, 기능 분류 |
| 제형별 적합도 | (신규) | 제형별 권장 사용량 |
| 배합 참고 | 교재 내 수치 데이터 | 제형별 상세 사용량 |
| 궁합 | (신규) | 원료 간 상호작용 정보 |
| 처방 활용 | (신규) | 제형별 처방 패턴 |
| 관련 규정 | `content/참조자료/ref_md/` | (기존 데이터 재사용) |

### 2.4 기존 데이터 재사용

```
기존 시험 데이터                    실무 DB
─────────────────────────────────────────────
content/참조자료/원료/              → 원료 기본 정보
  approved_ingredients.md              (사용 가능 원료)
  restricted_ingredients.md            (사용 제한 원료)
  banned_ingredients.md                (사용 금지 원료)

content/참조자료/ref_md/             → 관련 규정
  별표 1, 별표 2, 별표 4               (배합 기준, 표시 기준)

content/교재/                        → 원료 특성, 배합 원리
  2과목 원료학                         (원료별 설명)
  4과목 조제 실무                      (처방 원리)

src/keyword-index.js                 → 원료 ↔ 법령 교차 참조
  GLOSSARY_INDEX                       (용어집 → 원료 매핑)
```

## 3. AI 처방 참고 (Killer Feature)

### 3.1 포지셔닝

> **"AI 처방"이 아닌 "AI 처방 참고"** — 최종 처방 결정은 항상 조제관리사가 내립니다.

AI는 참고·보조 역할에 머물고, 법적 책임은 조제관리사에게 있습니다.

### 3.2 처방 참고 워크플로우

```
고객 요구
  ↓
"건조하고 민감한 피부"
  ↓
사용 가능한 원료 검색 (사용 가능/제한 원료 필터)
  ↓
원료 특성 분석 (보습력, 자극도, 궁합)
  ↓
처방 후보 생성 (3~5개 후보)
  ↓
배합량 계산 (한도 내 자동 계산)
  ↓
주의사항 표시 (궁합, 알레르기, 법적 한도)
  ↓
최종 조제 기록 (조제관리사가 최종 결정)
```

### 3.3 Wireframe

```
┌─────────────────────────────────────────────┐
│  🧪 AI 처방 참고                              │
│                                              │
│  고객 요구: [건조하고 민감한 피부      ]     │
│                                              │
│  [처방 후보 생성]                            │
│                                              │
│  ┌──────────────────────────────────────┐   │
│  │ 처방 후보 1: 보습 중심 세럼          │   │
│  │                                      │   │
│  │ �알루론산 0.5%  ── 보습              │   │
│  │ 글리세린 3.0%   ── 보습              │   │
│  │ 판테놀 1.0%     ── 진정              │   │
│  │ 알란토인 0.1%   ── 진정              │   │
│  │                                      │   │
│  │ 총 원료: 4종 / 총량: 100mL           │   │
│  │                                      │   │
│  │ ⚠️ 주의사항:                         │   │
│  │ • 히알루론산 + 고농도 비타민 C 불가  │   │
│  │ • 알란토인 0.1% 초과 시 주의        │   │
│  │                                      │   │
│  │ ✅ 법적 한도: 모든 원료 한도 내      │   │
│  │                                      │   │
│  │ [이 처방 채택] [수정] [다른 후보]   │   │
│  └──────────────────────────────────────┘   │
│                                              │
│  ⚠️ 본 결과는 참고용입니다.                  │
│  최종 처방은 조제관리사의 판단에 따릅니다.  │
└─────────────────────────────────────────────┘
```

### 3.4 안전 설계 원칙

| 원칙 | 설명 |
|------|------|
| **참고용 명시** | 모든 결과에 "참고용" 안내문 표시 |
| **최종 결정권** | 조제관리사가 최종 처방을 결정하고 기록 |
| **법적 한도 검증** | 모든 원료 배합량이 법정 한도 내인지 자동 검증 |
| **금지 원료 필터** | 사용 금지 원료는 처방 후보에서 원천 제외 |
| **알레르기 표시** | 알레르기 유발 향료 25종 자동 감지 및 경고 |
| **제한 원료 경고** | 별표 2 제한 원료 사용 시 직접 배합 불가 안내 |

## 4. 시험용 데이터 ↔ 실무용 데이터 통합

### 4.1 하나의 지식 그래프

시험 콘텐츠와 실무 콘텐츠가 별개의 제품이 아닌, 하나의 지식 그래프가 시험과 실무를 모두 지원합니다.

```
나이아신아마이드
       │
       ├── 📖 시험 공부
       │      ├── 법령: 별표 2 사용 제한 원료 여부
       │      ├── 성분 특징: 미백, 항염, 피부 장벽
       │      ├── 기출문제: 배합 한도, 효능
       │      └── 플래시카드: 정의, 수치, 용도
       │
       └── 🧴 실무
              ├── 성분 정보: INCI, 기능, 권장 농도
              ├── 처방 활용: 미백 세럼, 장벽 크림
              ├── 배합 참고: pH 5~7, 궁합 (히알루론산 ◎)
              ├── 조제 기록: 실제 사용 이력
              └── 관련 규정: 식약처 고시
```

### 4.2 데이터 통합 구조

```
┌─────────────────────────────────────────────┐
│              통합 지식 그래프                  │
│                                              │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐      │
│  │ 원료 DB │  │ 법령 DB │  │ 처방 DB │      │
│  │         │  │         │  │         │      │
│  │ 기본정보 │  │ 별표1~4 │  │ 처방전  │      │
│  │ 기능    │  │ 고시    │  │ 이력    │      │
│  │ 한도    │  │ 표시기준 │  │ 버전    │      │
│  └────┬────┘  └────┬────┘  └────┬────┘      │
│       │            │            │            │
│       └────────────┼────────────┘            │
│                    │                          │
│              ┌─────┴─────┐                    │
│              │ 교차 참조  │                    │
│              │ 엔진      │                    │
│              └─────┬─────┘                    │
│                    │                          │
│         ┌──────────┴──────────┐               │
│         ↓                     ↓               │
│   📖 시험 모드            🧴 실무 모드        │
│   (카드, 퀴즈, 모의고사)  (처방, 원료, 계산) │
└─────────────────────────────────────────────┘
```

### 4.3 기존 인프라 재사용

| 기존 모듈 | 시험 모드 역할 | 실무 모드 역할 |
|----------|--------------|---------------|
| `src/keyword-index.js` | 교재 ↔ 참조자료 매핑 | 원료 ↔ 법령 매핑 |
| `src/pdf-registry.js` | 참조자료 중앙 설정 | 법령 원문 참조 |
| `src/html-viewer.js` | 참조자료 뷰어 | 법령 원문 뷰어 |
| `content/참조자료/원료/` | 시험용 원료 목록 | 실무용 원료 DB |
| `content/참조자료/ref_md/` | 시험용 법령 원문 | 실무용 법령 참조 |
| `src/views/dictionary.js` | 성분 검색 (시험용) | 성분 검색 (실무용) |
| `src/views/trainer.js` | 배합 계산 연습 | 배합 계산 (실무) |
| `src/trainer-calc.js` | 계산 문제 생성 | 실무 배합량 계산 |

| 전환 | 조건 | 트리거 |
|------|------|--------|
| 시험 → 실무 | 합격자가 "실무 모드 시작" 클릭 | 사용자 선택 (자동 전환 아님) |
| 실무 → 시험 | 언제든 가능 | 사이드바 모드 토글 |
| 동시 사용 | 가능 | 두 모드 메뉴가 모두 표시 |

> **주의**: 합격자에게 실무 모드를 **강제하지 않습니다**. 시험 모드를 유지하거나 두 모드를 동시에 사용할 수 있습니다.

## 6. 처방전 라이브러리

### 6.1 개요

사용자가 직접 만든 처방을 저장, 버전 관리, 검색할 수 있는 개인 처방전 관리 시스템입니다.

### 6.2 처방전 구조

```
내 처방전

① 보습 세럼 A
   ├─ 원료 7종 (히알루론산, 글리세린, ...)
   ├─ 총량 100mL
   ├─ 조제일: 2026-08-15
   ├─ 고객 반응: "보습력 좋음"
   └─ 버전: v3 (최종)

② 민감 피부 크림 B
   ├─ 원료 6종 (세라마이드, 판테놀, ...)
   ├─ 총량 50g
   ├─ 조제일: 2026-09-01
   └─ 버전: v1

③ 두피 토닉 C
   ├─ 원료 8종 (살리실산, ...)
   ├─ 총량 100mL
   ├─ 만족도: 4.5/5
   └─ 버전: v2
```

### 6.3 버전 관리

```
보습 세럼
  v1 (초안)
   ↓
  v2 — 히알루론산 농도 변경 (0.3% → 0.5%)
   ↓
  v3 — 점도 조정 (카보폴 추가)
   ↓
  v4 (현재) — 최종 처방
```

### 6.4 데이터 모델

```json
{
  "id": "rx_001",
  "name": "보습 세럼 A",
  "version": 3,
  "parentVersion": 2,
  "status": "final",
  "ingredients": [
    {
      "name": "히알루론산",
      "inci": "Sodium Hyaluronate",
      "concentration": 0.5,
      "unit": "%",
      "limit": 2.0,
      "withinLimit": true
    }
  ],
  "totalVolume": 100,
  "totalUnit": "mL",
  "customer": {
    "id": "cust_001",
    "skinType": "건성",
    "concerns": ["건조", "민감"]
  },
  "notes": "보습력 좋음",
  "rating": 4.5,
  "createdAt": "2026-08-15",
  "updatedAt": "2026-09-01"
}
```

### 6.5 구독 유지 효과 (Lock-in Effect)

> 한번 쌓인 처방전 데이터는 다른 서비스로 옮기기 귀찮아지므로 **구독 유지율을 높이는 효과**가 있습니다.

| 데이터 | 축적 기간 | 이탈 비용 |
|--------|----------|----------|
| 처방전 이력 | 수개월~수년 | 처방전 재입력 공수 |
| 고객별 조제 기록 | 지속적 | 고객 이력 유실 |
| 버전 관리 이력 | 지속적 | 개선 이력 유실 |
| 원료 궁합 메모 | 지속적 | 경험 지식 유실 |

## 7. 법령·고시 업데이트 알림

### 7.1 개요

화장품 관련 법령·고시가 개정되면 실무 종사자에게 즉시 알립니다. 시험이 끝난 사용자도 계속 들어오게 만드는 이유가 됩니다.

### 7.2 알림 구조

```
┌─────────────────────────────────────────────┐
│  🔔 화장품 관련 규정 업데이트                │
│                                              │
│  2026년 9월 10일 새로운 고시가 반영되었습니다.│
│                                              │
│  변경 내용:                                   │
│  • 사용 제한 원료 변경 (별표 2)              │
│  • 표시 기준 변경 (별표 4)                   │
│  • 배합 기준 변경                             │
│                                              │
│  [내 처방에 영향 확인]                        │
│  → 3개 처방전이 영향을 받을 수 있습니다.      │
│                                              │
│  [전체 변경사항 보기]                        │
└─────────────────────────────────────────────┘
```

### 7.3 처방전 영향 분석

법령 개정 시 사용자의 기존 처방전에 영향이 있는지 자동 분석:

```
법령 개정: 별표 2 원료 X 한도 변경 (0.5% → 0.3%)
  ↓
사용자 처방전 스캔
  ↓
처방전 "보습 세럼 A" — 원료 X 0.4% 사용
  ↓
⚠️ "보습 세럼 A"가 새로운 한도를 초과합니다.
  → 원료 X 농도를 0.3% 이하로 조정 필요
  → [처방전 수정하기]
```

### 7.4 데이터 소스

| 소스 | 기존 활용 | 실무 확장 |
|------|----------|----------|
| `content/참조자료/ref_md/` | 시험용 법령 원문 | 개정 감지용 원본 |
| `src/pdf-registry.js` | 참조자료 중앙 설정 | 버전 추적 |
| `docs/dev/CHANGES.md` | 개발 변경 이력 | 콘텐츠 버전 관리 |

## 8. 구독 모델 재설계: 2단계 LTV

### 8.1 기존 모델의 한계

### 8.2 2단계 LTV 모델

| 단계 | 사용자 상태 | 제공 가치 | 구독 |

| 합격 직후 | 신규 합격자 | 실무 모드 자동 활성화 | 무료 체험 1개월 |
| 실무 | 조제관리사 | 원료 DB, 처방 참고, 계산 | ₩14,900/월 |
| 지속 | 실무 종사자 | 처방 관리, 법규 업데이트 | ₩14,900/월 |

### 8.3 가격 전략

| 플랜 | 가격 | 대상 | 핵심 가치 |
|------|------|------|----------|
| Free | ₩0 | 수험생 (체험) | 1과목 학습, 일일 10문제 |

## 10. 데이터 Flywheel

### 10.1 구조

```
시험 사용자
    ↓
학습 데이터 (카드, 퀴즈, 오답)
    ↓
합격
    ↓
실무 사용자
    ↓
처방 데이터 (원료 조합, 배합량, 고객 반응)
    ↓
원료/제형 데이터 축적
    ↓
AI 처방 참고 정확도 향상
    ↓
실무 가치 증가
    ↓
사용자 증가
    ↓
더 많은 데이터
    ↓
더 좋은 서비스
    ↓
(순환)
```

### 10.2 Flywheel 단계별 지표

| 단계 | 지표 | 측정 방법 |
|------|------|----------|
| 시험 사용자 증가 | DAU, 등록자 수 | 분석 도구 |
| 학습 데이터 축적 | 카드 암기율, 오답 패턴 | 기존 state.js |
| 합격률 | 합격자 수 / 응시자 수 | 사용자 자가 보고 |
| 실무 전환율 | 합격자 → 실무 모드 진입률 | 모드 전환 이벤트 |
| 처방 데이터 축적 | 처방전 수, 원료 조합 다양성 | 처방전 라이브러리 |
| AI 정확도 | 처방 참고 채택률, 수정률 | 처방 참고 분석 |
| 실무 가치 | 월간 활성 사용자, 구독 유지율 | 구독 상태 |
| 사용자 증가 | 추천 수, 신규 가입 | 분석 도구 |

### 10.3 사업적 의의

> 이 구조가 만들어지면 **단순 자격증 문제은행과 완전히 다른 사업**이 됩니다.

| 일반 자격증 플랫폼 | 본 전략 |
|-----------------|---------|
| 합격 후 이탈 | 합격 후 실무 전환 |
| 단일 수익 (시험 구독) | 2단계 수익 (시험 + 실무) |
| 데이터 축적 없음 | 처방 데이터 자산 축적 |
| 네트워크 효과 없음 | 커뮤니티 + Flywheel |
| 경쟁사 전환 용이 | 처방전 Lock-in으로 전환 비용 증가 |

## 12. 기술 아키텍처 영향

### 12.2 데이터 모델 (Supabase)

```sql
-- 처방전
CREATE TABLE prescriptions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES auth.users(id),
    name TEXT NOT NULL,
    version INT DEFAULT 1,
    parent_version INT,
    status TEXT DEFAULT 'draft' CHECK (status IN ('draft', 'final', 'archived')),
    ingredients JSONB NOT NULL, -- [{ name, inci, concentration, unit, limit, withinLimit }]
    total_volume NUMERIC,
    total_unit TEXT,
    customer_id UUID,
    notes TEXT,
    rating NUMERIC CHECK (rating >= 0 AND rating <= 5),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 고객
CREATE TABLE customers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES auth.users(id),
    name TEXT,
    skin_type TEXT,
    concerns TEXT[],
    notes TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 원료 실무 정보 (크라우드소싱 확장 가능)
CREATE TABLE ingredient_practice (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ingredient_name TEXT NOT NULL,
    inci_name TEXT,
    form_type TEXT, -- toner, serum, cream, etc.
    recommended_range TEXT, -- "0.1% ~ 2.0%"
    compatibility_good TEXT[], -- 잘 맞는 성분
    compatibility_caution TEXT[], -- 주의 성분
    prescription_use TEXT[], -- 처방 활용 태그
    source TEXT, -- 'official' | 'community' | 'ai'
    verified BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 법령 업데이트 이력
CREATE TABLE regulation_updates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title TEXT NOT NULL,
    description TEXT,
    affected_ingredients TEXT[],
    affected_prescriptions JSONB, -- 영향받는 처방전 ID 목록
    effective_date DATE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 13. 리스크 및 완화책

| 리스크 | 영향 | 완화책 |
|--------|------|--------|
| AI 처방 참고 오류 | 잘못된 처방 → 피부 문제 | "참고용" 명시, 최종 결정권 명시, 법적 한도 자동 검증 |
| 실무 데이터 부족 | 초기 원료 DB 빈약 | 기존 시험 데이터 재사용 + 점진적 크라우드소싱 |
| 합격자 실무 전환율 저조 | LTV 증가 미달 | 1개월 무료 체험, 기존 가격 유지 혜택 |
| 법령 업데이트 지연 | 실무 신뢰성 저하 | 정기적 법령 모니터링, 커뮤니티 제보 활용 |
| 커뮤니티 품질 관리 | 스팸, 잘못된 정보 | 관리자 승인 워크플로우, 신고 시스템 |
| Supabase 비용 증가 | 운영비 증가 | 처방전 데이터 압축, 비활성 사용자 아카이브 |
| 의료법적 이슈 | "처방" 용어 사용 | "조제 참고" 명시, 의료 행위가 아님을 안내 |
