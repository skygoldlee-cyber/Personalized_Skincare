# 교재 번호체계 가이드

> 본 문서는 `content/교재/` 내 8개 교재 Markdown 파일(표준형 4 + 이야기형 4)에 적용되는 **공식 번호체계**를 정의한다.
> 최종 갱신: 2026-09-13 (십진법 전환 완료)

---

## 1. 번호체계 개요

### 1.1 설계 원칙

1. **헤딩 기반**: 모든 구조적 레벨은 Markdown 헤딩(`###`, `####`, `#####`)으로 표현
2. **십진법 번호**: `N.`, `N.M`, `N.M.K` 형식으로 위계를 숫자로 표현
3. **목차 연동**: `###`와 `####`는 PWA 사이드바 목차에 표시
4. **본문 분리**: 세부 항목(`①`)과 설명(`•`)은 헤딩이 아닌 본문 텍스트
5. **챕터별 리셋**: `##`(대단원)마다 `###` 번호가 1부터 재시작

### 1.2 체계 전환 이력

| 시기 | 체계 | 비고 |
|---|---|---|
| 초기 | `(N)` / `①` / `가.` / `A.` / `a.` / `1)` / `①` | 7가지 기호 혼용 |
| 1차 개선 | `(N)` / `①` / `가.` / `1.` / `-` / `**굵게**` | 4가지 기호로 단순화 |
| **현재** | `N.` / `N.M` / `N.M.K` / `①` / `•` | **십진법 + 헤딩 유지** |

## 2. 번호체계 규칙

### 2.1 헤딩 레벨별 번호 형식

| 레벨 | 헤딩 | 번호 형식 | 예시 | 목차 표시 |
|---|---|---|---|---|
| 대단원 | `##` | `N.` (챕터 번호) | `## 1. 화장품법의 목적과 법령 체계` | O (Chapter) |
| 1단계 | `###` | `N.` | `### 1. 화장품법의 입법 취지` | O (섹션) |
| 2단계 | `####` | `N.M` | `#### 1.1 용어의 정의` | O (하위, 접기/펼치기) |
| 3단계 | `#####` | `N.M.K` | `##### 1.1.1 유지` | X (목차에 표시 안 됨) |

### 2.2 본문 레벨 번호 형식

| 용도 | 기호 | 예시 | 목차 표시 |
|---|---|---|---|
| 세부 항목 | `①` `②` `③` ... | `① 정신질환자` | X |
| 하위 설명 | `•` | `• 납세자의 인적 사항` | X |
| 강조 | `**굵게**` (기호 없음) | `**벌칙**` | X |

### 2.3 완전한 예시

```markdown
## 1. 화장품법의 목적과 법령 체계

### 1. 화장품법의 입법 취지(목적)

> 📌 **출처**: 화장품법 제1조

본문 설명...

#### 1.1 법령 체계

본문 설명...

##### 1.1.1 법령 위계

| 구분 | 법령 |
|---|---|
| 법률 | 화장품법 |
| 시행령 | 화장품법 시행령 |

#### 1.2 영업의 종류

① 화장품제조업 (등록)
② 화장품책임판매업 (등록)
③ 맞춤형화장품판매업 (신고)

• 제조업: 시설 기준 충족 후 등록
• 책임판매업: 품질관리 기준 준수
```

## 3. 번호 할당 규칙

### 3.1 리셋 규칙

| 헤딩 | 리셋 시점 | 예시 |
|---|---|---|
| `### N.` | `##`마다 1부터 재시작 | `## 1.` → `### 1.`, `## 2.` → `### 1.` |
| `#### N.M` | `###`마다 M이 1부터 재시작 | `### 1.` → `#### 1.1`, `### 2.` → `#### 2.1` |
| `##### N.M.K` | `####`마다 K가 1부터 재시작 | `#### 1.1` → `##### 1.1.1`, `#### 1.2` → `##### 1.2.1` |

### 3.2 본문 번호 규칙

| 기호 | 리셋 시점 | 비고 |
|---|---|---|
| `①②③` | 사용 위치에 따라 자유 | 참조용(`①, ② 중 하나`)은 줄바꿈 불필요 |
| `•` | 줄바꿈 없이 자유 사용 | 하위 설명 항목 |

### 3.3 금지 사항

- **잘린 헤더**: `#### ① 화장품제조업 또는 ...` (끝에 `...` 금지)
- **헤더-본문 중복**: 헤더 제목과 다음 줄 본문이 같은 내용
- **`###` 없이 `####`**: `##` 아래 `###`를 건너뛰고 `####` 금지
- **구 체계 잔재**: `### (N)`, `#### ①`, `##### 가.`, `#### 0.N` 금지
- **본문 강조 기호**: `**A. xxx**`, `**가. xxx**` 금지 → `**xxx**` 사용
- **본문 목록 알파벳**: `a. b. c.` 금지 → `① ② ③` 사용

## 4. PWA 목차 연동

### 4.1 목차 표시 범위

```
사이드바 목차
├── 📖 Chapter 01. 화장품법의 이해      ← ## (항상 표시)
│   ├── ▸ 1. 화장품법의 입법 취지        ← ### (표시)
│   │   ├── 1.1 법령 체계               ← #### (접기/펼치기)
│   │   └── 1.2 영업의 종류             ← #### (접기/펼치기)
│   └── ▸ 2. 화장품의 정의              ← ### (표시)
│       └── 2.1 화장품의 정의           ← #### (접기/펼치기)
└── 📖 Chapter 02. 개인정보 보호법
```

### 4.2 TOC 레벨 판정 로직

`src/views/textbook-reader.js`의 `_getTocLevel()`:

```javascript
function _getTocLevel(title) {
    const t = (title || '').trim();
    if (/^\d+\.\d+\.\d+/.test(t)) return 3;   // 1.1.1 (3단계)
    if (/^\d+\.\d+/.test(t)) return 2;         // 1.1 (2단계)
    if (/^\d+\./.test(t)) return 1;           // 1. (1단계)
    return 0;                                  // Chapter 등
}
```

### 4.3 헤딩 추출 로직

`_extractSubHeadings()`:

- `### ` 헤딩 → level 3 (목차에 표시)
- `#### ` 헤딩 → level 4 (목차에 표시, 접기/펼치기)
- `##### ` 헤딩 → **목차에 표시되지 않음**

## 5. 검증 체크리스트

교재 파일 변경 후 반드시 확인:

### 5.1 자동 검증

```powershell
# 파서 등가성
npm.cmd run build:data

# 유닛 테스트
npm.cmd test

# DOM 테스트
npm.cmd run test:dom
```

### 5.2 수동 검증 항목

| # | 항목 | 확인 방법 |
|---|---|---|
| 1 | `### (N)` 잔재 | `grep -r "^### (" content/교재/` → 0개 |
| 2 | `#### ①` 잔재 | `grep -r "^#### [①-⑳]" content/교재/` → 0개 |
| 3 | `##### 가.` 잔재 | `grep -r "^##### [가-하]\." content/교재/` → 0개 |
| 4 | `#### 0.N` 잔재 | `grep -r "^#### 0\." content/교재/` → 0개 |
| 5 | 잘린 헤더 | `grep -r "^#{1,6} .*\.\.\.$" content/교재/` → 0개 |
| 6 | `### N.` 연속성 | 각 `##`마다 1부터 순차 증가 |
| 7 | `#### N.M` 연속성 | 각 `###`마다 M이 1부터 순차 증가 |
| 8 | `##### N.M.K` 연속성 | 각 `####`마다 K가 1부터 순차 증가 |
| 9 | 헤더-본문 중복 | 헤더 제목과 다음 줄이 같지 않음 |
| 10 | `##` 아래 `###` 없이 `####` | `###`를 건너뛰는 `####` 금지 |

### 5.3 표준형-이야기형 동기화

- 표준형과 이야기형은 **동일한 번호 체계** 유지
- 같은 섹션 번호(`### N.`, `#### N.M`) 사용
- 이야기형에만 있는 서사(`#### 📖 민수의 상황`)는 번호체계에서 제외
